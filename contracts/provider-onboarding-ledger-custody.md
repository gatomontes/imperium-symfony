## Inspected mechanics and one owning lock

FormationJournal::changeAtHead passes mutable aggregate state and verified predecessor `{generation,digest}` under `citadel-formation`, writes a new frame only when state changes and publishes through rename after flushing the pending file. inspect observes the same verified chain under that lock. Keep frame schema, history and fixed storage custody unchanged. Existing fault tests demonstrate process interruption boundaries, not arbitrary machine power-loss durability.

AuthorityStore::state currently accepts only the seven-key v1 subtree. Admission::retain owns changeAtHead; Resolver::current and original own inspect. Act::verify, AuthorityStore::checkSource and currentTrust operate on supplied state without acquiring a journal lock. They are reusable verification mechanics, not evidence that an arbitrary supplied array is authoritative. Never call public retain/current/original/inspect/change from an already locked callback. Never read, resolve outside the lock, then use that answer to reserve.

Extract a package-internal CurrentAuthority verifier from Resolver into a pure `verify(store, onboardingState, authority, effect, termsRef, now)` path with no journal access. Keep Resolver's public signatures and conservative static-only refusal behavior unchanged by calling that core inside inspect. The B1 coordinator obtains state/head itself and calls the same core plus an internal typed CompletionResolver and finite readiness checks in its own changeAtHead callback. No public `verified`, `current`, `allow_dynamic`, supplied-state or callback parameter can bypass a check. Any internal verified projection is local to that callback and discarded at return; later checkpoints recompute it from the latest frame.

The shared internal core separates verified original/static facts from a closed list of typed unresolved completion obligations. That intermediate value is not current execution authority. Public Resolver keeps its existing final static gate and refuses obligations that B0 cannot satisfy. Inside its owning transaction, B1 validates each obligation against exact CompletionResolver originals and readiness rules before reservation; a core that unconditionally throws B0's dynamic refusal cannot then be reused by merely calling a completion checker afterward. No skip flag or externally supplied satisfied-obligation list is accepted. Test that the same missing prerequisite refuses through both public B0 and B1, while only the internal B1 path can resolve a genuine supported completion without relaxing public B0 behavior.

The dynamic extension recognizes B1 completion originals by exact schema/ref/producer and owning committed command/consumption, not by presence in B0 evidence. It must verify policy, slot, prerequisites and source provenance, including R1-R3 checks. Unsupported later-stage producers refuse. Do not globally relax B0's `DYNAMIC_PREREQUISITES_MISSING` behavior or reinterpret historic admission receipts. B0 new admissions continue to preserve first provenance on resupply; historical recognition continues before currentness checks and grants no new rights.

## Explicit subtree migration

New schema is `imperium.onboarding-authority-state/v2`. Exact top-level keys are the existing `schema,trust,acts,policies,evidence,revocations,admissions` plus `migration,bindings,sequences,commands,steps,slots,claims,applications,source_fences,attempt_outcomes,group_inputs,assessment_views,budget_bindings`. The extra maps belong to this one aggregate. bindings/applications and assessment_views remain empty until their selected producers exist; arbitrary insertion is invalid. Map entries must have supported schemas, exact key sets, bounded identities and verifiable cross-links.

Migration is an explicit local administrative code interface `migrate(expectedHead)`, distinct from enrollment, request admission, status and preview. It may migrate only an already enrolled, structurally valid v1 subtree. It checks current trust and exact head under changeAtHead, preserves the six existing payload fields and every retained raw byte, sets the new schema and empty new maps, and retains one H `imperium.bootstrap-state-migration/v1`. Its body is exactly `{from_schema,to_schema,predecessor_head,prior_subtree_digest,preserved_maps_digest}`; hashes bind canonical pre-migration data, not the resulting frame. Migration's own H belongs in `migration`, with sources containing the original enrollment receipt ref. It grants no authority, budget, enrollment or consumption. Repeating on a valid v2 returns its existing migration record without writing; malformed v2, unknown version or absent trust refuses. No downgrade, reset, key rotation or auto-migration on read.

Update AuthorityStore's strict state decoder for separately enumerated v1 and v2 shapes. B0 APIs must continue accepting both versions and preserve all B1 maps byte-for-byte when writing admission/revocation; v1 enrollment stays v1. The B1 coordinator requires v2. Older binaries refuse v2 safely and are not allowed to write it. Migration of a journal containing FC sessions preserves those original sessions/claims, including uncertainty, and grants no new shared budget association. Crash before publication leaves v1; after publication yields exactly one v2 migration. Test migration/revocation contention and restart without clearing consumption or exposure.

## Keys and exact public envelopes

Use F1's closed v2 advance, status and resume envelopes and immutable admission-result body unchanged. IDs use its bounds; refs for H remain `{schema,id,digest}`. The F1 request's policy reference `{id,version,digest}` is resolved against an admitted H policy's ID, `body.policy_version` and record digest, with exact schema and instance validation; never coerce it into a D2 ref without this lookup. F1 prefixed head digests are explicitly decoded at this new request boundary to FormationJournal's bare hash only after strict validation. Signed B0 act heads and originals retain their existing representation. Time is integer UTC seconds; checked milliseconds conversion is explicit. No float money or inferred units.

Persist map keys as canonical hashes of tagged tuples (store original tuple alongside the record and revalidate it):

| Map/right | Exact logical identity |
| --- | --- |
| sequences | `(instance_id,sequence_id)`; unique policy owner index derived from exact policy digest |
| commands | `(instance_id,sequence_id,command_id)`; advance and resume share this namespace |
| steps | `(instance_id,policy_digest,step_id)` across every sequence |
| slots | `(instance_id,policy_digest,slot_id)` across every sequence |
| signed authority consumption | `(instance_id,trust_fingerprint,nonce)`; separate from original-admission uniqueness |
| policy authority consumption | `(instance_id,policy_digest,slot_id)` |
| claims | exact command ref plus one owning step and one prepared-operation digest |
| source_fences | typed canonical original resource/effect lineage described below; never command/sequence/alias alone |

Store S/P consumption in slots' tagged authority-consumption entries or their owning claim, with uniqueness derived over all such entries under the lock; do not add a second authority journal. For S, both the one-use signed nonce and owning policy slot are consumed. For P, one slot is also the authority key, recorded once and referenced as both obligations. Every advancing step, including pure record/selection steps, consumes its global step key; pure steps have null slot and no S/P consumption.

Well-formed duplicate commands are recognized before new-head/currentness/readiness checks; retain the complete canonical envelope fingerprint and raw digest separately. Different bytes with identical decoded semantics recognize; changed semantic fields, including mode/head/predecessor/inputs, conflict. Malformed input never reserves IDs. Choose no durable record for pre-admission refusal: repeated refused requests are freshly evaluated, consume nothing and have no result_ref. This is F1's optional refusal-receipt choice made explicit. Preview never writes or reserves an ID. Registration binds one admitted policy, original budget and immutable initial refs; another sequence for that policy returns SEQUENCE_ALREADY_REGISTERED and its existing ref. New policies do not clear shared fences.

A successful admission result uses F1's exact body and result_digest, with observed_head the predecessor and no self-referencing digest. The resulting command_ref becomes sequence_head at publication, even if work is pending. Completion evidence is separate; it never changes that reference. Refusal, status and resume do not advance sequence_head. Only its proven finished predecessor allows a new advancing command.

## Reservation transaction and records

New advance inside one changeAtHead must: (1) recognize/conflict command; (2) check expected head, exact predecessor and immutable sequence binding; (3) resolve retained original policy/trust/authority/sources using the trusted clock; (4) identify exact owning step/slot, action/effect and run condition; (5) resolve genuine completed prerequisites and frozen inputs; (6) validate exact prepared operation, source-specific grant/commission, executor or current holder and minima of every expiry; (7) check unconsumed step, slot and S/P keys plus every shared source fence; (8) compute total exposure and concurrency; (9) atomically retain admission result, step/slot/authority consumption, original prepared bytes, group input if needed, claim and maximum reservation. Any refusal leaves all of these unchanged. No external I/O or nested lock occurs here.

New internal H schemas under prefix `imperium.bootstrap-` and suffix `/v1`:

| Record | Exact body |
| --- | --- |
| sequence-registration | `{sequence_ref,policy_ref,budget_ref,initial_evidence_refs,registration_command_ref}` |
| step-consumption | `{sequence_ref,command_ref,policy_ref,step_id,slot_id,authority_consumption,prepared_operation_ref,predecessor_head}` |
| step-completion | `{command_ref,step_consumption_ref,effect,result_refs,completed_at}` |
| source-fence | `{budget_identity,source_identity,command_ref,claim_ref,reason,predecessor_head}` |
| budget-binding | `{budget_ref,budget_identity,limit_ref,source_bindings,predecessor_head}` |

Pure steps use null slot_id, authority_consumption and prepared_operation_ref; non-I/O effectful steps use null prepared_operation_ref but require authority consumption. Effect is null only for pure completion. Completion result_refs are exact bounded original outputs; they cannot include a fabricated completion for a later-stage producer. Command results retain F1's exact non-H body and digest; do not add H fields to that closed body. Claims retain the exact F2 H claim body and tagged access/assessment variants, including explicit nullable response_ref only. A retained claim is immutable; custody updates are linked records/projections, never rewriting its digest or historical null response_ref. Completed claim response linkage is resolved through retained custody evidence.

In sequence-registration, sequence_ref is the logical pair `{instance_id,sequence_id}`, not a reference to the registration H itself. Compute the F1 registration admission result and its command ref first (neither includes this registration H); registration_command_ref then points to that immutable command. The registration H may be referenced by later records after its digest exists. This order must contain no record hashing itself through either sequence_ref or registration_command_ref. Declare and test the remaining exact internal custody-state entry schemas and linked-record storage layout before coding; their bounds and identity links must remain inside the enumerated v2 maps.

Limits: inherit B0 4 MiB bundle, 256 support records, depth 16, 8,192 source visits/records and 4,096 admissions. New ingress at most 1 MiB, 256 evidence refs; at most 4,096 retained commands, 256 sequences, 8,192 new H records across new maps, and the admitted finite graph bounds (never truncate). Count before writing and refuse LIMIT_EXCEEDED without eviction. Duplicate recognition remains possible at capacity. A command reserves at most one claim; no provider subcall loop. Response bytes cap 1,048,576. Overflow-checked integer subtraction before addition; no bound silently widens signed resource rights. Capacity limits are storage safeguards, not extra authorized attempts.

## One cross-type budget and uncertainty domain

Inspected FC uses FormationCognition::call and SessionExposure::reserve on `state.sessions[session_id].attempts`; it does not currently have a global D2 budget_ref. FormationClaimCustodyBroker::validate reruns that per-session check. Merely adding onboarding claims to another map is insufficient. B1 must add a pure SharedExposure calculator/validator over the same entire aggregate and invoke it in both FC's actual reservation path and onboarding's reservation, then again at their custody checkpoints. Keep FC's original typed validators and SessionExposure settlement rules. No second authoritative claim store or cached balance.

The budget-binding record binds an exact admitted budget source/limits to canonical source identities and existing FC session resource-decision identities. `source_bindings` is a finite list of tagged `{kind:formation,session_id,resource_decision_digest}` or `{kind:onboarding,policy_ref}`. Resolve every identity from retained legitimate originals. `budget_identity` is the hash of instance/Citadel and the original budget authority lineage, not an arbitrary budget ID, provider alias or policy digest. The source adapter must prove that lineage and limits; neither a caller-supplied binding record nor signature over unrelated material establishes equivalence. Missing real cross-type linkage refuses SHARED_BUDGET_SOURCE_UNRESOLVED. Default code cannot infer an association from same provider/account text. Tests supply exact public synthetic authority/resource originals through their real producer paths, not insert balances.

Bindings add restrictive accounting membership only, never enlarge an FC session's existing total/per-call rights. A source identity cannot move to another budget, split its maximum or lose membership while unsettled; conflicting associations refuse. With v2 shared accounting enabled, every new FC reservation must resolve its exact source association through this same coordinator (including sessions granted later); absent/ambiguous association refuses before reservation. Pre-v2 legacy behavior stays intact. This prevents a new FC session from escaping the shared accounting path; deployment compatibility must account for this deliberate new refusal. Unknown already existing FC obligations without verifiable separation conservatively block onboarding reservation. Do not pretend every legacy FC session has a signed D2 budget_ref.

Shared exposure is the sum of trusted settled usage plus maximum for each unsettled claim/attempt, counted once by canonical claim identity across aliases/projections. Existing FC source validators interpret FC records; B1 validators interpret bootstrap claims. Use `calls,input_tokens,output_tokens,cost_microusd,milliseconds`; new bootstrap meters permit nonnegative values with calls=1, so genuine zero-fee/zero-token access is representable. Do not relax SessionExposure::validate's positive FC maxima to force reuse. Require all dimensions within the exact shared limits AND original source-specific per-call/total limits. Selected P1-P9 ceilings remain 13 requests (12 cognition + 1 access), 730,000 ms, 1,200,000 micro-USD; cognition per attempt at most 100,000 micro-USD, 60,000 ms, 16,384 input and 4,096 output tokens. Exact approved total token meters come from the original policy. Access is one 10,000-ms GET /models with evidenced zero tokens/fee, no retry.

Concurrency one includes all unresolved in-flight effects in the identified shared domain. Source fences bind original budget lineage and immutable affected effect scope (credential operation/destination for access, holder/workload/configuration for cognition, exact root/window or assignment predecessor for later consumers). An unknown effect fences the shared domain and its source lineage, including across policy/sequence/command/alias changes. No rename, expiry, migration, abandoned command or new policy releases exposure or consumed rights. A new independent budget requires genuine separate authority and proven non-overlap; absent proof refuses. Policy approval here does not invent a new budget issuer effect.

## Credential/provider custody interfaces

Define fixed constructor-selected interfaces, not runnable adapter selection in request content:

- PreparedOperation: pure prepare/validate of exact non-secret wire bytes, method/destination, request digest, provider/model/configuration, tariff/token bounds, public credential operation, version and maxima. B1 refuses if a real compatible source is absent; O3-B0 provides the real implementation.
- SourceAuthority: separate access verifier (grant plus exact infrastructure executor, deployment custody, credential binding) and assessment verifier (commission plus current Augur holder). No nullable holder substitute, mixed tags, old formation claim relabeling or authority from an adapter name.
- CredentialCustody: issue once and consume once using opaque process-local capability at fixed infrastructure boundaries. Secrets exist only in the infrastructure callback; public claims/logs contain no capability or credential value. No serialization/reconstitution after process loss.
- ResponseCustody: validate attributable actual response ID, operation/claim identity, wire digest, usage and adapter provenance; retain immutable original response bytes and public validation metadata. Reconcile only those retained originals; caller-provided text is insufficient.

The B1 default implementations refuse without credentials/network. Offline doubles must implement these exact ports and count attempted issue/consume/dispatch, including malicious repeated callbacks. Do not add a general caller callback, network helper, endpoint override or environment lookup to public ingress. O3 adapters must cross B1's checkpoints rather than directly invoking provider code.

| Durable state | Allowed next boundary and proof |
| --- | --- |
| RESERVED | Same running coordinator may re-resolve current policy/act/slot/source/holder or executor, claim, prepared bytes, budget and expiry and commit DELIVERY_COMMITTED_OUTCOME_UNCERTAIN before issue |
| DELIVERY_COMMITTED_OUTCOME_UNCERTAIN | Issue outside lock once; verify returned capability matches original operation/expiry/scope; re-resolve under lock and commit CONSUMPTION_COMMITTED_OUTCOME_UNCERTAIN before consume |
| CONSUMPTION_COMMITTED_OUTCOME_UNCERTAIN | Inside the fixed infrastructure callback, re-prepare exact bytes, re-resolve under lock and commit DISPATCH_COMMITTED_OUTCOME_UNCERTAIN before dispatch outside lock |
| DISPATCH_COMMITTED_OUTCOME_UNCERTAIN | Validate actual response/usage attribution; commit RESPONSE_VALIDATED_PENDING_ENVELOPE with identity metadata; preserve maximum while envelope is absent |
| RESPONSE_VALIDATED_PENDING_ENVELOPE | Retain exact immutable envelope outside lock; compare it to committed metadata; a separate locked transition attaches RESPONSE_RETAINED |
| RESPONSE_RETAINED | Recheck immutable lineage, current prerequisites for new completion, typed response validity and settlement; commit outcome/usage/completion together or retain unknown exposure |

Every transition compares exact prior state and original claim/operation identities; no skip/backward transition. Commit predecessor head, never a self-referential final frame hash. Revalidation after reservation recognizes the exact consumed right owned by this claim; it checks currentness without trying to consume that right a second time. Revocation ordered before a checkpoint prevents that boundary; after dispatch commitment it cannot establish remote cancellation. Do not promise revocation between unlock and network transmission prevents a remote effect. Such uncertainty is retained under the declared B1 live gate.

After process loss, even RESERVED remains a consumed, exposure-bearing reservation: resume is evidence-only and never re-enters issue/consume/dispatch. No evidence of a call is not proof of no call. Fault after a durable checkpoint retains maximum even if the side-effect counter is zero. Only matching original retained evidence can reconcile an outcome; no refund/reissue based on exception, missing file or timeout. If response metadata/envelope commits succeeded but completion did not, recognize exactly that evidence once without a new action. Post-expiry/revocation historical completed effects remain recognizable. New progression and success views still require their governing current prerequisites; an unverifiable response or disputed completion remains fenced. Never alter FC's own historic recovery rules under a new B1 interpretation.

## Groups, terminal outcomes and application seam

Enforce retry v1.3.1: W2 after W1 success, W3 after W2; four distinct predeclared attempts per group; immediate success skips later slots. Freeze original semantic input/holder/configuration and resolved predecessor group outcomes at attempt 0. Retry compares to those exact bytes and needs the immediately prior attributable confirmed safe failure, settled or correctly retained exposure, unused right, current authority and shared capacity. Actual safe-retry allowlist is EMPTY; production CONFIRMED_RETRYABLE_FAILURE cannot be produced now. Tests of a hypothetical nonempty verifier are clearly isolated contract scenarios and cannot change the default allowlist.

Retain the exact retry amendment's non-H attempt-outcome schema; group-input and assessment-view bodies remain its exact H variants. Model text cannot classify safe failure or usage. Terminal invalid output with absent trustworthy usage retains exposure independently of progression status. Unknown or multiple group successes, missing prior outcomes or unfrozen inputs refuse. B1 defines completion interfaces for later attributable response/group producers; it does not manufacture O3 holder/results or O4 application outputs to make the graph finish.

The later application consumer must verify all W1/W2/W3 originals, exact approved medium-capacity tuple derivation and expected assignment generations, then consume the one application step/slot and publish the entire next assignment set plus receipt in the same B1 transaction. This pass only declares that seam. B0 receipt, raw O1 proposal, successful transport or completed assessment alone cannot satisfy application authority.
