Native registry/bootstrap successor interpretation is deliberately unsupported by the new current consumer.

## Acquisition order and internal seams

The implemented typed-writer order is **Formation → native → bootstrap or target-specific storage lock**. This is not yet a whole-supported-set global order: direct generic storage is outside it. Formation-only operations stop at Formation. The native registry has no additional journal lock. Bootstrap locks are not reentrant; callers do not nest `StateStore::locked`. Target-specific immutable/mutable locks are ordered after the common boundary only when reached through an already-owned typed caller. Direct generic entry is not covered.

`FormationOwnerFrame::run` acquires the unchanged `AtomicTransition::run('citadel-formation', ...)`, constructs a private, process-local capability and invalidates it in `finally`. It does not make AtomicTransition reentrant. A capability rejects another canonical root, serialization and use after scope exit. `FormationJournal::inspect`, `change` and `changeAtHead` pass it as an additional internal callback argument. Existing callbacks keep their historical argument meanings. `inspectExisting` retains its existing read-only shared-lock implementation; it does not issue a writable owner capability.

`NativeBoundary::lock` acquires Formation before the native lock. Its existing same-process nesting map now retains the actual live Formation capability, not a boolean assertion that Formation was held. Nested native operations receive that capability. Cross-root native nesting refuses before a second Formation acquisition, including a foreign StateStore injected into V0. `NativeBoundary::inOwner` first verifies the capability against the exact root and then consumes it without reacquiring Formation. It is not a request-controlled flag. Formation-owned callers must use this explicit seam; calling a fresh Formation acquisition from inside a Formation callback is still forbidden.

The root owner consumes the frame through `OperatorRootOwnership::nativeInOwner`. Root onboarding schema validation and `B225_FRESH_ROOT_OWNED` remain intact. `native` enters through the native owner boundary, which either acquires Formation/native in order or passes the already-held frame from the real outer native owner. This also covers old callers through pinned `StateStore::locked`, whose callback signature and bytes remain unchanged.

V0 enters `RequiredV0PersonnelInstallationService::withOwner` before bootstrap locking. It passes the capability to `installInOwner` and `sealInOwner`. Direct/required installation and operationalization recheck the same root owner in those seams. The root installer was already indirectly fenced by Formation before PPC3; this change resolves its callers' ordering, not a previously unfenced direct installation.

The smallest proposed next boundary is a reviewed versioned generic-storage target/owner contract: route or refuse every reserved institutional target before the primitive's own lock, retaining exact old storage semantics for other targets and passing an already-held frame from typed callers. Adding an unused new wrapper alone cannot close the old generic paths. Any change to the pinned primitive requires its actual successor review, not a newly calculated ledger hash in this campaign. This is a source-contract conflict, not an invitation to grant model or installation authority.

## Proof bounds

The new process test proves both actual registry-enrollment/current-consumer orderings within the typed-writer subset, verifies the physical Formation lock with a nonblocking independent handle, bounds child completion, tests interrupted direct installation and tests V0/MasterMason and StateStore/required installation in fresh processes. Existing native tests retain actual competing revisions, revocation, retirement, historical replay and interruption coverage. The complete gate supplies compatibility evidence for the other listed entry points.

There is no positive current native-registry or bootstrap successor adapter. Those are synchronized refusals, not unfenced exclusions. Constable/Guildhall binders require bootstrap state, whose publication already makes the artifact-backed model-bound current path unavailable; their later publication is still fenced. Existing historical `actor/witness`, old-schema candidate/receipt behavior and `inspectExisting` do not gain a transferable currentness certificate from this work.

The direct generic writer gap is executable: `testGenericStorageRemainsAnOpenWriterPathButCompletedRetirementRefuses` successfully acquires the Formation lock nonblockingly inside a generic mutable guard. A completed retirement then refuses in the current consumer, but this does not prove serialization during that write. Unknown generic successor forms also refuse after publication; their race remains outside the supported synchronized subset.
