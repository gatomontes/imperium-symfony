## Changed test map

`NativeAssignmentChronologyTest::testSignedPolicyCannotAdmitAnUnresolvedTargetOriginal` has A and B data sets. It authenticates the exact fresh Operator signature before invoking policy admission and checks no head change.

`NativeAssignmentChronologyTest::testRealNativeMappingAndDirectVerifierReachTheProtectedChronologyBoundary` directly constructs NativeAssignmentEvidence using real native services; no permissive AssignmentEvidence mock participates. Its same-root state is created through actual FRESH/native owners. Its policy is the real earlier fixture policy, not edited accepted bytes. Each refused tuple/admission is identified as an attempted input, not a successful application.

`NativeProfileOriginalBoundaryTest::testCourtthaneCompetentOriginalRefusalsAndSuccessorMapping` and `NativeLocksmithOriginalBoundaryTest::testLocksmithCompetentOriginalRefusalsAndSuccessorMapping` share `Support/NativeProfileOriginalCase.php`. Together they exercise twelve separately signed substantive candidate refusals and both successor/appointment/mapping joins, with an independent disposable root for each Seat. Those are candidate-level facts. `profile.fits`, native application and protected delivery are not marked proven.

`Support/NativeAssignmentProof.php` only signs disposable fixture originals through actual delegates, calls actual appointment owners, captures reached RuntimeException messages, and exports selected public arrays. Signing secrets stay in memory. It does not implement a native evidence verifier or write accepted state.

`Support/native-assignment-reader.php` reconstructs the actual store and fixed native services in a fresh PHP process. Its settings resolver uses the same native verifier object. It repeats the direct earlier source refusal and reaches MODEL_SETTINGS_ABSENT for each role. It does not import a holder/application or report current use. The parent bounds the compound process to 300 seconds (store reconstruction, direct verifier and both role reads), records the native exit and verifies the head is unchanged.

All failed diagnostic attempts remain in evidence. Developmental before/after source snapshots identify overlapping documentation work; only the committed full gate determines candidate totals. Diagnostic, prestep and signature verification counts are never added to PHPUnit gate totals.
