## Campaign sequence

Campaign countdown at selection: eight stages including Preparation Batch 0.

0. **Preparation Batch 0 — native integration inventory.** Resolve the exact
   native producers, stores, lifecycle authorities and consumers; classify each
   missing join and define the smallest acyclic correction sequence.
1. **Batch 1 — native principal competence and authority lineage.** Establish an
   exact Operator Root-authorized transition scope and native principal →
   decision → issuance target → custody → single-use authority chain. A constant
   edit, configured digest or caller-sealed record cannot self-constitute it.
2. **Batch 2 — native successor provenance.** Implement canonical production
   successor and creation readers with exact instance, generation, lifecycle,
   operation, source-digest and eligibility validation.
3. **Batch 3 — canonical v3 admission and binding consumer.** Implement the
   existing La Cortine admission schema and an authoritative operation-scoped
   binding reader while preserving the immutable `BOUND_INACTIVE` descriptor and
   keeping provider effects closed.
4. **Batch 4 — native atomic integration.** Join the corrected native sources to
   the retained transition store and consumer so missing or changed native state
   refuses before publication.
5. **Batch 5 — native contention, interruption and lifecycle proof.** Re-run
   separate-process contention, every affected cut, expiry, revocation and
   competing principal/successor changes through the actual native chain.
6. **Batch 6 — reconstruction and adversarial audit.** Independently reconstruct
   the native-to-receipt chain and challenge resealed source substitution, stale
   lifecycle state, schema substitution, reader bypass and secret leakage.
7. **Batch 7 — separately sequenced terminal Blackquill audit.** Begin only from
   clean merged Batch 6 main and decide the bounded canonical transition claim.

A refusal or correction batch expands the estimate. No later planned stage
authorizes an earlier one.

## Hard boundary

principal scope; create, migrate or activate a principal or successor; issue or
consume authority; write native or transition state; implement v3 admission;

capabilities; invoke a provider; perform external I/O; authorize retry; or open
Iron Gate or Lazaretto.

`BOUND_INACTIVE`, native v3 `NOT_IMPLEMENTED` and
`UNKNOWN_REPLAY_PROHIBITED` remain binding.
