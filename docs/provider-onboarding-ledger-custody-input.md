# O2-B1 implementation shapes

Declared before runtime coding against reviewed preparation 0399b581e8e61b5306813479df6a8af363c35c0a. Internal names are not public authority. The governing ledger/custody contract remains controlling.

All maps stay inside onboarding v2 under FormationJournal. Each map uses a canonical tagged tuple hash and stores that tuple. Sequence entries are {key,registration,head}; command entries {key,request,raw_digest,result,ref}; step entries {key,consumption,completion}; slot entries {key,command_ref,authority_key}; claim entries {key,record,operation,maximum,settled,custody}; budget bindings are {key,record}. source_fences hold H originals. Other future maps remain empty. Strict readers validate exact fields, H digests, map keys and linked commands/consumption. Bounds are checked before publication.

Custody is a list of immutable H checkpoint records, in the owning claim entry. Checkpoint schema imperium.bootstrap-custody-checkpoint/v1 body is {claim_ref,operation_digest,stage,previous_ref,response_metadata,response_envelope}. previous_ref is null only for the first DELIVERY checkpoint. response_metadata is null before validated response and otherwise {provider_response_id,operation_digest,response_digest,usage,provenance}. response_envelope is null until retained and otherwise {claim_ref,operation_digest,response,metadata}; response bytes are public and capped. The immutable claim's response_ref remains null; its custody chain supplies response linkage. Stages are DELIVERY_COMMITTED_OUTCOME_UNCERTAIN, CONSUMPTION_COMMITTED_OUTCOME_UNCERTAIN, DISPATCH_COMMITTED_OUTCOME_UNCERTAIN, RESPONSE_VALIDATED_PENDING_ENVELOPE, RESPONSE_RETAINED. Checkpoints bind predecessor via H sources and never contain secrets/capabilities. Final step completion and settlement publish in one transition.

The fixed PreparedOperation port prepares exact public operation {schema,wire,destination,method,provider,model,configuration_ref,credential_operation,adapter,maximum,expires_at,authority_source}, with schema imperium.bootstrap-prepared-operation/v1. The SourceAuthority port verifies that source-specific operation against exact admitted terms and state, returning no authority flag. Default ports refuse unsupported adapter/holder sources. CredentialCustody issues an opaque process-local capability and consumes it once via the coordinator-owned callback; no callback is accepted in a request. ResponseCustody dispatches and retains/reads the immutable envelope through fixed constructor-selected infrastructure. Default implementations perform no I/O. Recovery reads only retained evidence and never issues/consumes/dispatches.

Budget source association is derived from an exact source record explicitly bound by the signed admitted policy budget_ref. Its kind is shared-budget and decoded content is {schema,lineage_ref,limits,formation_sources}; schema imperium.bootstrap-budget-association/v1. lineage_ref resolves an original budget-root source whose closed content is {schema,limits}, schema imperium.bootstrap-budget-root/v1. The root original identity and limits must match across every policy association; a source cannot be remapped. formation_sources is a finite list of {session_id,resource_decision_digest}; actual retained formation signatures/resource decisions are verified, not inferred from provider strings. Record source_bindings adds the exact current policy ref only after its admission (avoiding policy self-hashes). This binds restrictive accounting, never new FC permission. Generic B0 source text is not this typed lineage and refuses by default. Synthetic tests sign these exact budget terms through the real B0 policy producer and use actual FC grants.

F1 has no extra authority/prepared-input fields. The coordinator derives P authority from the owning slot and exact policy admission, or finds the unique retained S original matching that policy/effect/terms. No caller supplies satisfied obligations. Pure configuration retains exact frozen configuration refs; SELECT_BASE requires a fixed pure projection port over current retained inputs and refuses absent compatible input conversion. Missing O3/O4 producers refuse before consuming their steps.

## Final interface refinements

Claim entry operation is {record,prepared}: the immutable prepared-operation-record H body is {operation}; prepared repeats those exact public operation bytes and strict state validation compares them. The claim/step prepared_operation_ref resolves that retained H. The fixed SourceAuthority port also validates the original response and returns SUCCEEDED or TERMINAL_FAILURE; no caller classification is accepted. Generic transport success is insufficient for completion. Defaults refuse absent source/response producers. Each receipt remains in the sole aggregate; response ports retain immutable public envelopes outside the lock only after committed identity metadata.

AssessmentGroups implements finite group conditions, genuine linked outcome resolution, exact frozen input/holder/configuration/wire identity and outcome creation from validated retained custody. The actual retry allowlist remains empty, so no confirmed retryable failure can be produced. Initial assessment still requires real founding/holder completion and a compatible fixed port; none is manufactured in B1. Independent group-interpreter tests demonstrate refusals without pretending to supply that later producer. Runtime positive access/FC custody uses actual B0/FC synthetic authority producers. Assignment and founding producers remain absent.

No separately verified independent-budget producer is available: registration refuses a different canonical budget lineage after one has been registered. A new policy referencing the same original lineage shares all exposure and source fences. Pure/effectful steps cannot escape an outstanding onboarding unknown fence through a new policy/sequence. Status/preview and historical recognition remain non-authorizing.

Public status heads convert verified journal bare digests into the explicit F1 sha256: form; B0 signed originals and predecessor fields keep their declared journal format. Response/currentness checks do not provide remote cancellation. Process loss after RESERVED never resumes credential delivery. Prepared expiry must not exceed the exact slot and authority admission expiry. Source-specific validation must establish any additional grant/holder expiry.

The shared FC hooks are narrow calls at real FormationCognition reservation and FormationClaimCustodyBroker validation, preserving pre-v2 behavior and original schemas. The bounded implementation adds one actual mechanical runtime candidate, CommandLedger, through the existing additive inventory mechanism; the original inventory byte prefix and frozen snapshots remain unchanged.

The AuthorityStore constructor additionally accepts an already fixed FormationJournal object for internal FC verification. Existing string-root construction is unchanged. The FC shared gate builds this view from its actual owning journal, trusted clock and retained enrollment identity, then revalidates both the original budget association and limit source under the existing lock. No new lock is acquired and no request controls a root or trusted-state parameter. Revoking an association's original policy therefore stops new FC reservation/custody even while the independent FC session grant remains valid.
