## Why this campaign exists

The merged continuation/exclusivity correction proves fresh-empty-registry
refusal, not actual process-bound custody. PHP serialization, cloning and fork
inheritance are untested; no runtime process-incarnation fact is issued or
checked. Forward receipt completion also remains reachable through the callback
execution method without a distinct governed reconciliation boundary.

The prior campaign additionally violated its planned merge/audit sequence and
left the canonical steps/flow at Preparation Batch 0. This campaign repairs the
runtime proof and the institutional proof. It performs no live effect.

## Governing question

Can Imperium make first-callback custody non-transferable across serialization,
clone, fork and fresh-process boundaries; separate provider execution from
forward evidence reconciliation; and close the remediation only after a clean
merged, independently tested and correctly recorded baseline?

The campaign may close only if:

- capability issuance records an ephemeral process-incarnation identity derived
  from the actual runtime rather than authority prose;
- use verifies the current process incarnation and exact issuer custody;
- issuer and capability serialization/unserialization and cloning fail closed;
- forked or independently started processes cannot use inherited or restored
  custody to publish callback start;

  fabricated continuation object;
- Batches 1–4 are separately authorized, committed and merged before Batch 5;
- Batch 5 begins from clean synchronized merged Batch 4 `main`, runs focused and
  full tests, and records local and GitHub CI evidence separately; and
- canonical steps, flow and handoffs match the actual disposition.

## Planned sequence

1. **Preparation Batch 0 — process, serialization, recovery and provenance
   inventory.** Trace serialization, cloning, fork/inheritance, process identity,
   service/container lifetimes, execute/reconstruct/forward paths, authority

   correction and proof plan. Documentation only.
2. **Batch 1 — process-incarnation and recovery contracts.** Define the
   non-serializable/non-cloneable continuation/issuer invariants, runtime process
   identity source, fork/PID-reuse posture and separate callback, reconstruct and
   forward-recovery authority contracts. No runtime consumer change.
3. **Batch 2 — process-bound custody implementation.** Bind issuance and
   consumption to the actual process incarnation; reject serialization,
   unserialization, clone and inherited/fresh-process use. No provider edge.
4. **Batch 3 — execution/reconciliation separation.** Make callback execution
   validate live custody first; move read-only reconstruction and sealed-response
   forward binding behind distinct APIs and governed claims. Provider doubles
   only.
5. **Batch 4 — adversarial/application proof.** Prove serialized issuer+capability
   transfer refusal, clone refusal, fork refusal where supported, fresh-process
   refusal, forward-recovery authorization, callback non-reinvocation, container
   lifetime and all prior tuple/substitution/interruption invariants without
   credential, network or external I/O.

   committed and merged, start a new clean-main audit, require GitHub CI,
