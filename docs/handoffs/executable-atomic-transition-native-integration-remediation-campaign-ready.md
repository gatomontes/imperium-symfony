## Refusal traps

Preparation must reject any proposal that obtains apparent integration by:

- merely adding a scope field or changing a status constant;
- renaming the new admission schema as the canonical schema;
- treating configured hashes as native provenance;
- promoting fixture or offline successor stores into production sources;
- treating an unread binding projection as effective state; or
- weakening the existing terminal refusal or closed provider-effect boundary.

`BOUND_INACTIVE`, native v3 `NOT_IMPLEMENTED` and
`UNKNOWN_REPLAY_PROHIBITED` remain binding.
