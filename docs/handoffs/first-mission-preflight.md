# Run one bounded local installation preflight

Time budget: ten minutes. Stop after one report; no background task or retry loop. Do not run PHP application commands, tests, benchmarks, CI, Composer installation, profiling, enrollment, signing, activation, provider calls or mission execution. Do not reopen O4 or implement O5. This is the immediate installation-observation step for MISSION.md.

1. Establish the operator-designated actual installation path. A development worktree or historical `E:\htdocs\imperium` path is not proof of the running installation. If the installation is not identified in the local session, ask only for that path and stop; do not scan unrelated directories or assume the current worktree is live.
2. Run `Observe-Installation.ps1 -InstalledRoot '<confirmed path>'`. It reads Git identity/tracked-drift metadata with optional locks and fsmonitor disabled, inspects committed presence of the relevant source paths, and optionally obtains PHP's version without loading php.ini. It creates a new report directory in Downloads only. It does not establish a running executable identity, installed dependency health or authority.
3. Read only already supplied, explicitly identified public readiness/commissioning evidence. Do not search `.env`, credential stores, private keys, private runtime journals or raw private state. No public evidence file was included here: `public-evidence-request.json` is the existing empty schema template, not evidence. Unknown fields stay null. Never fill them with synthetic fixture values or assertions inferred from Git.
4. Report genuine evidence availability for installation, trust, institutions, appointments and transport. Distinguish not supplied from absent. Record source identity separately from running-process identity and deployment. State the observed O4/O5 acceptance limitations using the latest supplied evidence; do not claim new GitHub acceptance without verification.
5. Use source/read-only documentation to identify the first unmet prerequisite for the target Courtyard-to-result route. Give one exact next action, responsible owner and required public artifact. If an exporter would read private state or create locks, describe that footprint and do not run it in this metadata-only preflight. Do not bootstrap or migrate state to make inspection succeed.
6. Return the generated observation JSON, a short PRECHECK-RESULT.md, and any explicitly supplied public evidence by reference/hash only. Do not include raw private evidence. Include commands, exits and limitations. Do not produce an empty completion packet or treat the supplied files as a successful mission.

Keep the report short. A concrete missing installation/evidence item is a useful outcome. No additional test run is needed to explain it.
