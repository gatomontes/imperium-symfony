## Independent corrective review

This review is external to the local run that created and self-audited the
candidate. It inspected the committed diff, central runtime implementation,
contract, race tests, application proof, terminal evidence and exact changed-file
scope.

The candidate uses a two-attempt optimistic manifest comparison around the
complete nested inspection derivation. It records existence, membership, entry
type and content digest across the declared project-root read set. Continued
instability refuses conservatively. It introduces no public snapshot token,
freshness lease, authority field, provider permission or retry grant.

The established authorizing broker retains its native exclusion lock. Unlocked
CLI/direct inspection remains non-authorizing. The candidate does not make a
returned result linearizable or transferable and correctly admits that it may
become stale immediately after return.

The separate-process evidence addresses transition/migration publication,
revocation, expiry, interruption, repeated stable reads, two-attempt churn and
inspector termination. Application evidence covers the real Symfony reader,
CLI and journal-bound broker while asserting no credential, callback or provider
effect.

## Residual boundaries

Acceptance remains limited to cooperative single-host atomic-rename storage.
It excludes network filesystems, physical power loss, hostile same-content ABA,
state outside the declared project root, linearizable freshness after return,
leases, signatures, cache transfer and admission transfer.

The two-attempt cap bounds repeat attempts, not scan duration. Lock-file contents
remain non-semantic. Production binding of the optional checkpoint is prohibited.
