# Next campaign: Continuous Agent Governance Controls

## Purpose

Imperium must prove that identity, authority, evidence, and control remain valid throughout operation—not merely at the moment a decision is sealed. Control strength must grow with consequence while preserving the separation among accountable owner, competent Office and Seat, Persona, Profile, Officer process, Manifestation, credential holder, and any future disposable sortie.

This campaign follows the completed Institutional Decision Integrity campaign. It extends that decision evidence toward runtime validity; it does not reopen or reinterpret the completed decision contracts.

## Starting state

- The Delegate Mission route is terminal at Step 69.
- Runtime Integrity Hardening is terminal through Step 35.
- The four crash demonstrations are complete.
- Credential-boundary remediation is terminal through Batch 17.
- Institutional Decision Integrity is terminal through Batch 6.
- The runtime already contains multiple principal identifiers, single-use authority records, leases, journals, custody transitions, immutable Folia, terminal audits, and reconstruction mechanisms.
- Iron Gate, Lazaretto, sorties, generalized revocation, telemetry, containment, and incident handling remain unopened future boundaries.

## Preparation Batch 0 — inventory and campaign design

Inspect existing contracts, services, persistence, tests, and canonical documentation. Produce one exact inventory covering:

1. runtime principals and where each identity is bound;
2. authority and credential leases, including scope, holder, consumer, expiry, freshness, consumption, supersession, and revocation fields;
3. governance-event equivalents already emitted through immutable records, Folia, transition journals, and provider journals;
4. existing restriction, interruption, invalidation, retirement, and terminal-return mechanisms;
5. reconstruction and audit coverage from decision through runtime result and retirement; and
6. precise gaps against `todo/continuous-agent-governance-controls.md`.

The preparation output must distinguish four states for every requirement: `EXISTS_CANONICALLY`, `EXISTS_FRAGMENTED`, `ABSENT`, or `DEFERRED_BOUNDARY`. It must name exact source files and tests, identify competent actors, and propose the smallest safe campaign sequence.

## Preparation constraints

Batch 0 is read-only with respect to runtime behavior. It may add or update inventory, analysis, campaign, and handoff documentation plus documentation-consistency tests if needed. It may not:

- define a new runtime principal or merge existing principals;
- create or widen an authority lease;
- implement Iron Gate execution or sortie receipts;
- implement Lazaretto admission;
- implement revocation propagation or a kill switch;
- add telemetry, anomaly detection, containment, or incident workflows;
- migrate another credential or provider path;
- alter any completed Delegate, Senate, Guildhall, Garrison, Curia, Conscription, Clavium, or La Cortine judgment; or
- create Delegate Mission Step 70, Runtime Integrity Hardening Step 36, Credential Boundary Batch 18, or Institutional Decision Integrity Batch 7.

## Proposed post-inventory sequence

The following order is provisional until Batch 0 proves what already exists:

1. canonical runtime-principal bindings and consequence tiers;
2. canonical governance-event envelope over existing immutable transitions;
3. execution-time authority-lease contract and revalidation boundary;
4. revocation and interruption propagation;
5. telemetry and Curia reassessment intake;
6. incident preservation, containment, and closure lineage; and
7. perimeter adoption through separately authorized Iron Gate and Lazaretto campaigns.

No implementation batch may begin merely because it appears in this provisional list. Batch 0 must identify the actual first missing boundary and preserve everything already proved.

## Preparation completion criterion

Preparation is complete when a reviewer can see, without searching unrelated logs:

- which continuous-governance controls Imperium already possesses;
- which controls exist only as fragmented lifecycle-specific implementations;
- which controls are absent;
- which controls belong to unopened perimeter boundaries;
- which actor owns each judgment or enforcement point; and
- the smallest next implementation batch that does not duplicate, widen, or reopen completed work.

`docs/continuous-agent-governance-controls-preparation-inventory.md`. It classifies all 56
requirements and identifies consequence vocabulary plus authority-empty principal references
as the smallest first implementation boundary.

Batch 1 adopts `imperium.continuous-governance-consequence-classification/v1` on the existing
internal governance-cognition request only. It records `ADVISORY_COGNITION` /
`INTERNAL_REVERSIBLE`, references the existing instance, competent Office, target Seat, and
native authority, and leaves every authority-bearing flag false. It does not create or merge a
principal, change the native authority, authorize cognition by itself, or open an external,
revocation, telemetry, containment, or incident boundary.

Batch 2 adopts `imperium.continuous-governance-event-envelope/v1` on that same existing
governance-cognition request. The independently sealed envelope references the exact native
Folium and authority, records `AUTHORIZATION_REQUEST` / `REQUEST_NOT_AUTHORIZATION`, carries
the Batch 1 consequence and principal references, and explicitly records that no action was
attempted and no effect completed. It is not telemetry, does not replace the native judgment,
and grants or consumes no authority.

Batch 3 adds the read-only `imperium.continuous-governance-internal-reconstruction/v1` view for
one completed internal governance-provider iteration. It verifies exactly seven native
artifacts from the Batch 2 event and classified request through Imperator decision, Clavium
lease, durable claim, provider journal, and response envelope. Missing or substituted evidence
fails stopped. The view mechanically excludes the cluster-native authority record, decision-
integrity bundle, Delegate pre-deployment governance, deployment, custody, retirement, native
post-provider result, external effects, telemetry, revocation, containment, and incidents;
none may be inferred as validated.

Batch 4 adopts `imperium.internal-cognition-lease-controls/v1` on newly issued operational and
governance cognition leases. It normalizes freshness evidence, exact scope, supersession,
invalidation, and stop conditions and revalidates that metadata at durable-claim time. The

lease is closed, and no propagation or kill-switch path exists. Historical immutable leases

Batch 5 seals `imperium.continuous-governance-revocation-authority-design/v1`. It assigns no
omnibus revoker: Seneschal owns bounded mission restriction/interruption judgment, Imperator
owns consequential reauthorization and instance-wide emergency judgment, Clavium remains the

telemetry, containment, incidents, and perimeter scopes remain unimplemented.

Batch 6 corrects the terminal competence statement and defines the separate
`imperium.continuous-governance-revocation-disposition/v1` and
`imperium.continuous-governance-enforcement-authority/v1` schemas. The disposition is judgment
only and cannot mutate state or open authority. The enforcement record is separately bound,

Batches 7–10 implement and reconstruct one deliberately narrow `INTERRUPT` slice for an exact
durable governance cognition invocation claim before provider-journal admission. Seneschal
judgment, a separate expiring single-use Locksmith authority, native admission enforcement, and
a four-artifact read-only reconstruction are complete. No source claim, lease, credential, or
occupancy is mutated, and no propagation or perimeter authority is opened.

Batch 11 assesses that completed slice and selects one unclaimed governance cognition lease as
the smallest adjacent scope. Selection opens no authority and changes no runtime behavior. The
next sequence must proceed one batch at a time from lease-scoped disposition through separate
authority, native claim-admission enforcement, and reconstruction while leaving the immutable

Batch 12 adds only the lease-scoped Seneschal `INTERRUPT` disposition issuer. It shares the
