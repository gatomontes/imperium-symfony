## Three different replacement questions

1. **Initial application:** blocked by the order above before W1/W2/W3 for actual native targets. Modes A and B only differ at application authority; neither resolves source admission.
2. **Binding-only replacement:** O4 can select only a complete set already in the original fixed allowed set, against its retained assessment view. The native mapping embeds the immutable model-bound Profile, whose exact PPC5 correspondence fixes binding/configuration. A changed binding/model/configuration cannot be hidden under that same Profile. An unchanged semantic binding with a new authorization/immutable Profile revision still changes the mapping. No distinct positive binding-only native replacement is demonstrated here; the broader compatibility fixture does not supply one.
3. **Profile or holder-generation replacement:** `NativeProfileOriginalBoundaryTest` and `NativeLocksmithOriginalBoundaryTest` each make an actual successor designation. Mapping refuses **PPC7_MAPPING_INDEPENDENT_HOLDER** until the separate generation-2 appointment occurs. The next authentic mapping has a different exact source reference, even though the native binding reference is unchanged. AssignmentRule::tuples requires equality with the original policy target; ApplicationOwner::replace retains that policy and assessment view. This successor component is not an O4 application replacement.

Policy::validate could independently admit a separately signed second policy with different complete sources. That is not forbidden as a generic admission operation, but it cannot reset founding or application consumption, change the first holder's policy linkage, or cause ApplicationOwner::replace to use a different assessment scope. This run does not use that technique to manufacture a positive chain. PPC8's accepted consumed-root regression remains unchanged.

## Minimal new contract proposal — NOT APPROVED / NOT IMPLEMENTED

Two distinct decisions are needed; approval of one does not settle the other.

**C1: staged exact target admission and assessment scope.** Specify a versioned post-establishment authorization object bound to the original founding policy, root, completed establishment, current native holder and exact existing exposure/consumption ledger. Only after native mapping originals exist may the competent Operator authorize their exact pair, finite allowed tuple sets, original requirements and selection rule, and a separately defined W1/W2/W3 assessment scope. Preserve prior raw signed bytes, consumed root, budgets, nonces, session/custody boundaries and historical receipts. Define an explicit atomic migration/link accepted by policy, input construction, admission, application and settings owners. No unresolved reference is treated as an admitted original. This necessarily changes protected O4 target/assessment contracts; it cannot be implemented as a local fixture or a new arbitrary evidence-admission effect under the old policy.

**C1 replacement extension:** choose explicitly whether successor Profiles/holder generations may receive a new exact assessment scope, with their own separately signed complete-pair change, predecessor application and original consumption linkage. Binding-only changes must either preserve the exact approved Profile correspondence or undergo the same immutable revision/examination/qualification procedure. No generic source substitution, standing amendment power or policy reset is proposed.

**C2: substantive `profile.fits` source contract.** Define its exact required judgments for each Seat and candidate binding, competent producers, required original findings and qualification criteria, treatment of external capability/access/cognition inputs, and a bounded verification derivation. The existing contract supplies exact institutional findings and qualification facts but no closed equation equating them to this historical synthetic predicate. The [predicate specification](provider-assignment-use-predicates.md) makes that gap explicit. A new definition needs review; an admitted PASS or parsed FIT claim is not the definition.

These proposals identify minimal required decisions, not a finished schema or an assertion of authority. Full native application/use, race/interruption proof and receiving acceptance remain dependent on them. No runtime workaround was introduced.
