## Why this campaign exists

Imperium now has bounded evidence for:

- executable native atomic transition;
- canonical operation/root interpretation at the established consumer;
- conservative exclusion of competing legacy readers;
- coherent non-authorizing inspection under cooperative single-host storage;
- durable pre-effect claims, journals and historical receipt reconstruction.

The native email route still stops before provider execution. That refusal is
correct: a committed native transition and a coherent inspection result are not
effect authority. The next unanswered question is whether one exact native chain
can authorize one controlled provider effect, consume its authority and
capability at the proper pre-I/O cut, and bind the provider outcome to a durable
receipt without reviving a legacy corridor or inventing retry authority.

## Governing question

Can Imperium admit exactly one provider effect from an exact current native root,
with explicit Operator authority, one-time capability custody, atomic pre-I/O
consumption, interruption-safe unknown-outcome semantics and independently
verifiable receipt provenance?

Eight later stages follow Preparation Batch 0. Each batch requires a new explicit

## Authorization grammar

This campaign selection authorizes Preparation Batch 0 only.

The following do **not** authorize a later batch or a live effect:

- preparing or selecting this campaign;
- “continue,” “proceed,” “forward,” “clear,” or a Latin motto by itself;
- a green focused or full test suite;
- a campaign document that says a later batch is planned;
- authority inferred by an agent from urgency, convenience or prior patterns;
- a request to push, merge, review, update steps or write the next prompt.

Batches 1–6 and 8 require an explicit message naming the batch. Batch 7 additionally
requires the exact live-trial marker above. If authority is absent or ambiguous,
stop without runtime mutation or external I/O.
